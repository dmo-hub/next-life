# แตกใบงาน

แตกสเปกเป็น issue 1 ใบต่อ 1 PR ใช้กับงานที่เจ้าของเคาะแล้วเท่านั้น ยังไม่เคาะให้กลับไปที่ issue เสนองาน

## ขั้นตอน

1. อ่านสเปกและบล็อก "คำตอบที่ตัดสิน" ทุกข้อต้องลงใบใดใบหนึ่ง
2. อ่านโค้ด ถ้ามีงานจัดของเดิมที่ทำให้ใบถัดไปง่าย แยกเป็นใบแรก
3. แบ่งเป็นเส้นบาง แต่ละใบผ่านทุกชั้นที่จำเป็น (เนื้อหา engine จอ ด่าน) จนเล่นหรือวัดได้เอง ไม่แบ่งตามชั้น
4. ใส่ใบที่ขวางของแต่ละใบ ถ้าใบหนึ่งใช้ของที่อีกใบสร้าง นั่นคือเส้นขวาง เช็กด้วยว่าไม่วนกัน
5. งานปรับหน้าจอ ใบแรกคือหน้า tweak ให้เจ้าของเลือก ตาม `next-life-contributor/references/process.md`
6. ตรวจทุกใบก่อนยื่น
   - เสร็จแล้วเปิดหรือรันอะไรให้เห็นได้ ไม่มีคำตอบแปลว่าแบ่งผิด
   - เกณฑ์รับงานต้องตกได้ คือวันนี้ยังไม่จริง และวัดด้วยตา คำสั่ง หรือไฟล์
7. ยื่นรายการให้ผู้ใช้ ถามว่าขนาดใบ เส้นขวาง และการรวมแยกตรงใจไหม แก้จนยอมรับ

## แม่แบบใบ

```markdown
## ทำอะไร
พฤติกรรมที่ใช้ได้เมื่อจบใบ

## เกณฑ์รับงาน
- [ ] สิ่งที่เห็นหรือคำสั่งที่วัดได้

## ด่าน
ด่านตามชนิดงาน

## ถูกขวางโดย
#<เลข issue> หรือ ไม่มี
```

เปิดตามลำดับที่ไม่มีตัวขวางก่อน ใช้ `gh issue create` ถ้าเครื่องมี ไม่มีให้ส่งข้อความให้ผู้ใช้วางเอง
