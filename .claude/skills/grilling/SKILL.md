# จี้ถามก่อนลงมือ

ถามผู้ใช้จนทุกข้อที่ต้องตัดสินถูกตัดสิน มองงานเป็นต้นไม้ของการตัดสินใจ ข้อหนึ่งตอบแล้วเปิดข้อถัดไป

## ก่อนรอบแรก

- อ่าน `design/<เรื่อง>/decisions.md` และ `design/<เรื่อง>/MAP.md` ให้จบ ข้อที่เจ้าของเคาะแล้วไม่ถามซ้ำ
- ค้นคำหลักของเรื่องทั่ว `design/` ด้วย กติกาอาจอยู่ในเรื่องข้างเคียง
- ข้อเท็จจริงในโค้ดเป็นหน้าที่คุณ ค้นเอง อย่าถามผู้ใช้

## ทำเป็นรอบ

- แต่ละรอบถามทุกข้อที่ถามได้ตอนนี้ ข้อที่คำตอบขึ้นกับข้ออื่นในรอบเดียวกันให้รอรอบถัดไป
- ใช้ `AskUserQuestion` ถ้ามี รอบละไม่เกิน 4 ข้อ ตัวเลือกแรกคือคำแนะนำ ลงท้าย "(แนะนำ)"
- ตัวเลือกที่แทนกันได้ใช้เลือกข้อเดียว เลือกหลายข้อใช้เมื่อทุกตัวจริงพร้อมกันได้
- ศัพท์ที่ผู้ใช้ไม่ได้พูดก่อน อธิบายครึ่งบรรทัดในคำถาม

## ตัวเลือกคือคำกล่าวอ้าง

- ตัวเลือกที่อ้างกลไกเดิม ต้องค้นโค้ดก่อน และใส่ `ไฟล์:บรรทัด@sha` ในข้อความ
- ค้นคำเดาได้ 0 ไม่ได้แปลว่าไม่มี ให้ค้นคำในกติกา lint และชื่อที่ engine export
- ตัวเลือกที่ขัดข้อเดิมใน `decisions.md` ต้องบอกว่าขัดข้อไหน หรือตัดออก

## ตรวจย้อนก่อนจบ

เมื่อไม่มีคำถามเหลือ โจมตีทุกข้อที่ตัดสินแล้วด้วย 3 คำถาม

1. สมมติฐานไหนยังไม่เช็กกับของจริง
2. ทางเลือกไหนไม่เคยยื่น
3. ผลข้างเคียงไหนไม่มีใครคิดราคา

งานดีไซน์เกมหรือหน้าจอ ให้ใช้ agent `design-challenger` แทนการตรวจเอง ข้อที่อ่อนหรือพังกลับไปถามผู้ใช้เป็นรอบใหม่

## จบ

เมื่อผู้ใช้ยืนยันว่าตรงกัน พิมพ์บล็อกนี้ด้วยคำของผู้ใช้เอง ไม่แปลงความ ข้อที่ผู้ใช้ไม่ได้พูดไม่ใส่

```
## คำตอบที่ตัดสิน
1. <หัวข้อ>: <คำตอบตามที่กด>
```

บล็อกนี้ไปอยู่ใน issue เสนองาน ข้อที่ต้องให้เจ้าของเกมเคาะแยกเป็นหัว "ต้องให้เจ้าของเคาะ" ห้ามเขียนว่าเจ้าของเคาะแล้วถ้าไม่มีคำตอบของเจ้าของจริง
