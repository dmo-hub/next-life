# โปรเซสทำงาน next-life

ทุกคนที่ทำงานเข้า repo นี้เดินทางเดียวกัน ไฟล์นี้บอกลำดับ ส่วนขั้นตอนคำสั่งอยู่ใน `../SKILL.md`

## ลำดับ

เสนอ → เจ้าของเคาะ → ใบ → ทำ → ด่าน → พร้อมตรวจ

1. **เสนอ** ไอเดียใหม่เปิด issue ด้วยฟอร์ม "เสนอสายหรือระบบใหม่" ยังไม่ต้องเขียนโค้ด
2. **เจ้าของเคาะ** รอคำตอบใน issue เจ้าของตัดสินดีไซน์ ตัวเลขสมดุล และเนื้อการ์ด ก่อนเสนออ่าน `design/<เรื่อง>/decisions.md` ข้อที่เคาะแล้วห้ามเสนอขัดโดยไม่บอก
3. **ใบ** เคาะแล้วได้ issue ที่ assign ให้ 1 issue = 1 ใบ = 1 PR
4. **ทำ** branch `lane-<ชื่อคุณ>/<ชื่อใบ>` จาก main ล่าสุด
5. **ด่าน** รันตามชนิดงานด้านล่าง
6. **พร้อมตรวจ** เปิด PR กรอกแม่แบบครบ แล้วรอผลตรวจใน PR

## ทำแค่โจทย์ในใบ

- ไอเดียนอกใบ เปิด issue ใหม่แล้วกลับมาทำงานเดิม อย่าแถมใน PR
- ใบละ branch ใบละ PR ให้เล็กพออ่านจบ ระบบใหญ่แบ่งหลายใบ
- ไม่แน่ใจให้ถามใน issue หรือ PR อย่าเดา ข้อที่ตีความเองเขียนในหัว "ต้องให้เจ้าของเคาะ"

## งานปรับหน้าจอ: มีหน้า tweak ก่อนลงจริง

งานที่เปลี่ยนหน้าตาหรือจัดหน้าใหม่ ต้องให้เจ้าของเลือกจากของจริงก่อนลงเกม

1. ใบแรกทำหน้า tweak ใต้ `docs/dev/tweak/` ให้ปรับค่าและเทียบแบบได้ ไม่แตะหน้าเกมจริง
2. ติดป้าย `wait` (รอเจ้าของเลือก) ในแถวของหน้านั้นที่ `docs/dev/index.html` แล้วเปิด PR
3. เจ้าของเลือกแล้วค่อยมีใบลงเกม ใบนั้นวัดค่าฐานจากเกมจริงก่อน ไม่ลอกจากหน้า tweak อย่างเดียว
4. ลงครบแล้วลบหน้า tweak พร้อมแถวของมันในใบเดียวกัน

## ลำดับคิว

ใบ tweak และใบที่ขวางใบ tweak ตรวจก่อน รองลงมาคือ UI และเอกสารล้วน ซึ่งลัดคิวได้เพราะไม่กระทบเกม งาน engine และเนื้อหาตรวจทีหลัง เพราะต้องรันด่านยาว ถ้าแบ่งงานได้ แยกส่วน UI หรือเอกสารเป็นใบของตัวเอง

## ด่านตามชนิดงาน

ทุกชนิดงานรันชุดนี้ก่อน

```bash
node build.mjs
npm run lint:test
npm run harness:test
npm run site:check
npm run check:data
```

แล้วเปิด `docs/play.html` เล่นส่วนที่แก้จนเห็นกับตา console error ต้องเป็น 0

**UI หรือเอกสารล้วน** (ไม่แตะ `src/engine` `src/node` `content` `harness` `package.json`): ชุดนี้พอ

**แตะ engine หรือเนื้อหา**: รันด่านที่ใบระบุเพิ่ม เรียก harness ตรง เพราะ `npm run <ด่าน> -- --n 500` ไม่มีผล

```bash
node harness/run.mjs --n 4000 --seed 1
node harness/titles.mjs --n 1000 --gens 3 --seed 1
node harness/family.mjs --n 1000 --seed 1
node harness/lineage.mjs --n 1000 --gens 3 --seed 1
```

ด่านหนัก `full` ผู้ดูแลรันตอนตรวจ PR

**ย้ายโค้ดหรือ refactor ที่บอกว่าไม่เปลี่ยนผล**: พิสูจน์ด้วย lifehash เทียบกับฐาน

```bash
node harness/lifehash.mjs --base origin/main --world life --n 30
```

**ด่านตก**: ด่านสุ่มตกตาม seed ได้ ก่อนสรุปว่าใบทำตก รันด่านนั้นเทียบ main ที่ seed 1 2 3 แล้วลงตัวเลขทั้งสองฝั่งใน PR ตกจริงก็บอกตามจริง อย่าติ๊กผ่าน

## ส่งงาน: เลขต้องมี sha

- ด่านทุกตัวในเนื้อ PR บอกตัวเลขและ sha ที่วัด
- เลขที่ไม่ได้วัดเองห้ามเขียนเป็นข้อเท็จ ให้เขียนว่ายังไม่วัด
- ถ้า push commit เพิ่มหลังวัด เลขเดิมใช้กับ sha ใหม่ไม่ได้ ต้องวัดใหม่
- ร่างโน้ต whatsnew ใส่ในเนื้อ PR ไม่แก้ไฟล์เอง
