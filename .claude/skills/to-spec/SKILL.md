# เขียนสเปกลง issue

เรียบเรียงจากสิ่งที่รู้แล้ว ไม่ถามรอบใหม่ สเปกอยู่ในเนื้อ issue ฟอร์ม "เสนอสายหรือระบบใหม่" ไม่สร้างไฟล์ใน repo และไม่แก้ `design/`

## ขั้นตอน

1. อ่านโค้ดส่วนที่เกี่ยวและ `design/<เรื่อง>/decisions.md` ใช้ศัพท์เดียวกับเกม
2. เช็กทุกข้อกับบล็อก "คำตอบที่ตัดสิน"
   - ทุกข้อในบล็อกอยู่ในสเปก ด้วยคำเดิม
   - ทุกข้อในสเปกย้อนไปหาคำผู้ใช้ได้ ข้อที่คุณเดาหรือเติมเองย้ายไปหัว "คำถามค้าง"
3. บอกว่าจะวัดผลงานนี้ที่จุดไหน ใช้ด่านใน `harness/` ก่อนสร้างด่านใหม่ แล้วถามว่าตรงกันไหม
4. เขียนตามแม่แบบ แล้วให้ผู้ใช้เปิด issue หรือเปิดด้วย `gh issue create` ถ้าเครื่องมี

## แม่แบบ

```markdown
## ขอบเขต
ทำอะไร ไม่ทำอะไร

## ผู้เล่นเห็นอะไร
เรื่องที่ผู้เล่นเจอบนจอ ตามลำดับ

## ตัวเลขที่ต้องเคาะ
ค่าที่เสนอ และที่มาของค่า

## การ์ดหรือไฟล์เดิมที่แตะ
รหัสการ์ด ระบบ หรือ path

## วิธีวัด
ด่านที่ใช้ และค่าที่ต้องได้

## แบ่งได้กี่ PR
ลำดับใบ

## คำถามค้าง
ข้อที่ผู้ใช้ยังไม่ได้พูด หรือรอเจ้าของเคาะ
```

สเปกไม่ใช่คำตัดสิน ตัวเลขสมดุล ดีไซน์ และเนื้อการ์ดรอเจ้าของเคาะก่อนแตกใบ
